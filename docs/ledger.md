# qabench ledger — every defect in the kit, and what it taught

One row per error the kit itself produced or failed to see. The kit is the one copy six projects run, so a defect here is a defect in six places at once, and the generalisation is the deliverable — the fix is the smaller half.

| date | what happened | found by | class (qa-framework check) | generalisation | the change |
|---|---|---|---|---|---|
| 2026-09-05 | Every keychain lookup failed on the first live run: `-a account` was spliced between `-s` and its value, so six real credentials read as "no credentials" | the first run against tharros staging | C8 (a verdict that does not depend on the thing it measures) | a branch that only executes on one OS is a branch no CI test executed; stub the OS call and assert the exact command | 0.1.2: argument order fixed; `test_keychain_lookup_builds_a_command_security_accepts` |
| 2026-09-05 | A CSRF-protected login form (tharros `_csrf` / `tharros_csrf`) refused the kit's bare POST with 403, which reads exactly like a wrong password | reading tharros' `auth.csrf_protect` before the run | C9 / C4 | a refusal for PROTOCOL must be told apart from a refusal for CREDENTIALS, or the stage lies in both directions — accepts when the form has CSRF and the manifest does not say so, and reports a dead credential when the password was right | 0.1.1: `login.csrf_field`; one `post_login` helper for login and the wrong-password probe; two tests, one per direction |
| 2026-09-05 | The sixth role met tharros' login throttle (5 a minute per IP) and the stage read the 429 as a dead credential; the wrong-password probe then PASSED on the same 429 | the first live run | C8 | a rate limit is not a verdict about the code and must never be counted as one, in either direction | 0.1.3: 429 waited out and retried; the probe SKIPS on 429; sessions cached across stages so six roles × three stages is six logins, not eighteen |
| 2026-09-05 | The author piped the sweep's stdout through `\| grep \| head -80` and read a truncated ledger as the run's result | the author, reading four ledgers that the pipe had not shown | C8 (the reporter is part of the checker) | never put a long-running checker's stdout through a filter that can close early; log to a file, read the ledgers | operating rule in this file; runs now redirect to `/tmp/qabench-<project>-run.log` |
| 2026-09-05 | 13 tharros admin pages scroll the whole document sideways at 390px — real findings that would have made the first night red and the lane switched off within a week | the first live sweep (384 cells) | C10 | a new check over an old surface finds the debt all at once; the debt must be RECORDED per page with a reason and only allowed to shrink, never pardoned wholesale or failed wholesale | 0.1.5: `pages.sideways_allow` ratchet — a listed page skips with its reason, a fixed page asks to be removed, an unlisted one fails |
| 2026-09-05 | A 600px fixture block overflowed the desk viewport too, so the phone-only test failed on a correct stage | the kit's own test | — (fixture) | a fixture that exists at exactly one viewport is the only fixture that discriminates the two | fixture widened to 600px (between 390 and 1440) |
| 2026-09-05 | 144 of 528 tharros cells skipped for want of a path id — every `{car_id}`-style page unmeasured | the first live sweep | C10 (partial vacuity) | a sweep that skips a third of its surface must say so in a count the reader sees, and the project owes an `ids` provider | printed as `decided N cells over M routes`; tharros owes `scripts.qa.route_matrix:resolve_ids` |
