# Test heuristics — Hendrickson, Lyndsay, Emery (Test Heuristics Cheat Sheet), cut to what a web app in a warehouse or an office exposes
Data — for every field: NOTHING (blank, empty list, zero rows) · TOO MUCH (the longest REAL value on this system, a 5,000-character paste, 10,000 rows) · BOUNDARY (0, 1, max, max+1, the last cent, the last day of the month, an id that does not exist) · WRONG TYPE (letters in a number, a date as text) · DUPLICATE (the same barcode twice, the same name twice) · NEGATIVE and ZERO money · UNICODE (Hebrew beside Latin and digits, an emoji, a right-to-left mark) · WHITESPACE (leading, trailing, only).
Sequence — do A then B: choose then type over it · sort then page · filter then select then act · edit then cancel · save then reload · back after a write · the same click TWICE (double tap) · the wrong ORDER (the second step before the first) · INTERRUPT (switch tab, lock the phone, lose the network mid-write, return).
State — a record in every status the form declares, including the ones the data never holds · an empty account (no groups, no permissions) · a scope that is empty rather than absent · a record with zero children, one child, many children.
Time — the boundary of the day, the month, the year · a deploy while a tab is open · a session that expires under a half-filled form · a value entered yesterday read today.
Multi-user — two tabs on one record · another role editing what you are looking at · a webhook or a sync landing during a save.
Documents — the printed thing scanned with the device in use · the longest name on a label · both paper orientations · reprint twice and compare.
Copy — every sentence in the product's language · plurals agree · a sentence that names the state it moves TO is not the state it is IN · an error says what happened AND what to do.
